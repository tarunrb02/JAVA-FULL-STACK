it is passing down propertes and methods from parent class to child class.

Note: If Child and parents have same methods, child's method will be used. (Method Overriding)

example: 

class Parent {
    constructor() {
        this.name = 'Parent';
    }
    hello() {
        console.log('Hello from Parent');
    }

    sleep() {
        console.log('Parent is sleeping');
    }
    work() {
        console.log('Parent is working');
    }
}

class Child extends Parent {
    work() { 
        super.sleep(); // Call the sleep method from Parent class
        console.log('Child is working');
    }
    constructor() {
        super(); 
        this.name = 'Child';
    }
}

let childInstance = new Child();
console.log(childInstance.name); // Output: Child
childInstance.hello(); // This will call the hello method from Parent class since it's not overridden in Child class
childInstance.work(); // This will call the work method from Child class

# JavaScript DOM (Document Object Model) – Complete Notes
The Document Object Model (DOM) is a programming interface for HTML and XML documents. It represents the webpage as a tree of objects, allowing JavaScript to access, modify, add, or remove HTML elements dynamically.

# What is the DOM?
When a browser loads an HTML document, it converts it into a tree-like structure called the DOM Tree.

The document object is created by the browser (Chrome, Edge, Firefox), not by Node.js.

# `textContent` vs `innerHTML` vs `innerText`
-----------------------------------------------------------------------------------------------------
These three DOM properties are used to read or modify the content of an HTML element, but each behaves differently.

1. `textContent: textContent returns or sets all the text inside an element, including text inside child elements. It ignores HTML tags and includes hidden text.

### Example

```html
<p id="demo">
    Hello <b>World</b>
    <span style="display:none">Hidden</span>
</p>
```javascript
const demo = document.getElementById("demo");
console.log(demo.textContent);
```

### Output
Hello World Hidden

### Characteristics

* Returns only text (no HTML tags).
* Includes hidden text (`display: none`, `visibility: hidden`).
* Ignores CSS styling.
* Faster than `innerText` because it does not calculate styles.
* Can also be used to replace all text inside an element.

# 2. `innerText`: `innerText` returns or sets **only the text that is visible on the webpage**.

### Example

```html
<p id="demo">
    Hello <b>World</b>
    <span style="display:none">Hidden</span>
</p>
```javascript
console.log(demo.innerText);
```

### Output

Hello World //The word **Hidden** is not returned because it is not visible.

### Characteristics

* Returns visible text only.
* Ignores hidden elements.
* Respects CSS (`display`, `visibility`, etc.).
* Preserves line breaks as shown on the page.
* Slightly slower because the browser must calculate the rendered layout.

# 3. `innerHTML`: `innerHTML` returns or sets the **HTML markup inside an element**, including all child tags.

### Example

```html
<p id="demo">
    Hello <b>World</b>
</p>
```javascript
console.log(demo.innerHTML);
```

### Output

```html
Hello <b>World</b>
```

### Characteristics

* Returns HTML along with text.
* Includes all child elements and tags.
* Can be used to create or replace HTML dynamically.
* Useful for adding formatted content.
* Be careful when inserting user input, as it can lead to **Cross-Site Scripting (XSS)** vulnerabilities.

# Visual Example

### HTML

```html
<p id="demo">
    Hello
    <b>World</b>
    <span style="display: none">Hidden</span>
</p>
```

### JavaScript

```javascript

```

### Output

| Property      | Output                                                        |
| ------------- | ------------------------------------------------------------- |
| `textContent` | `Hello World Hidden`                                          |
| `innerText`   | `Hello World`                                                 |
| `innerHTML`   | `Hello <b>World</b> <span style="display:none">Hidden</span>` |

# Comparison Table

| Feature                   | `textContent`  |  `innerText` |  `innerHTML`     |
| ------------------------- | -------------  |  ----------- |  --------------- |
| Returns text              | ✅ Yes         | ✅ Yes      | ✅ Yes           |
| Returns HTML tags         | ❌ No          | ❌ No       | ✅ Yes           |
| Includes hidden text      | ✅ Yes         | ❌ No       | ✅ Yes (as HTML) |
| Respects CSS              | ❌ No          | ✅ Yes      | ❌ No            |
| Preserves HTML formatting | ❌ No          | ❌ No       | ✅ Yes           |
| Can modify HTML           | ❌ No          | ❌ No       | ✅ Yes           |
| Performance               | Fastest        | Slower       | Moderate         |

# Quick Revision

* `textContent` → Plain text, includes hidden text, ignores HTML tags.
* `innerText` → Only visible text, respects CSS, ignores hidden content.
* `innerHTML` → Returns or sets HTML markup, including child elements and tags.

--------------------------------Fetch API------------------------------------------

const response=await fetch(URL);

+ fetch(URL) sends an HTTP request to the given URL.
+ fetch() returns a Promise.
+ The Promise resolves to a Response object.
+ await pauses the async function until that Promise is resolved.
+ So response contains the server's HTTP response, not the actual JSON data yet.

const data=await response.json();

+ response.json() reads the response body and parses it as JSON.
+ response.json() also returns a Promise.
+ await waits for that Promise to resolve.
+ data contains the actual JavaScript object/array obtained from the JSON.

Note: One important point: fetch() does not reject its Promise for HTTP errors like 404 or 500. You normally check response.ok before parsing/using the data.
