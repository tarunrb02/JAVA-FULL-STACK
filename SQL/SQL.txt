Relational model: (E F Codd)
--------------------------
+ He said, all the data will be stored in the form of tables
+ Any DBMS which follows relational model will becomes RDMS

Rules of E F Codd
1. Any data entered into the cell must be single valued data
2. we can stored data in multiple tables, if we want to establish the relation b/w the tables we have to use Key attributes
3. All the data will be stored the form of table including metadata
4. Data will be validated in 2 steps
	+ By assigning the Datatypes ---->(Mandatory)

DATA TYPES:
1. NUMERIC TYPE OF DATA:
	- TINYINT(1BYTE)
	- SMALLINT(2 BYTE)
	- MEDIUMINT(3 BYTE)
	- INT(4 BYTE)
	- BIGINT(8 BYTE)
	- DECIMEL(M, D)->(8 BYTE):  Exact fixed-point number
	- FLOAT(4 BYTE)
	- DOUBLE(8 BYTE)

2. CHARECTER TYPE OF DATA:
	- CHAR: Fixed-length string => REMAING BITS WILL BE SPACE PADDED
	- VARCHAR: Variable-length string => IT CONSUME ONLY REQUIRED MEMORY SPACE
	- TEXT: Variable-length TEXT BLOCK 64KB OF TEXT
	- TINYTEXT: 255 BYTES OF TEXT
	- LONG TEXT: 4.29GB OG TEXT

3.BLOB: Binary Large Object for raw data like images, files, or encrypted text

4. Date and Time Data Types: These types allow tracking of chronological data & automatically validate dates.
	- DATE: Format YYYY-MM-DD. Range: 1000-01-01 to 9999-12-31.
	- TIME: Format HH:MM:SS. Tracks time or time intervals.
	- DATETIME: Format YYYY-MM-DD HH:MM:SS. Range: Year 1000 to 9999.
	- YEAR: Stores a 4-digit year format. Range: 1901 to 2155.
	- TIMESTAMP: Format YYYY-MM-DD HH:MM:SS. Universal time; ranges from 1970 to 2038. Often auto-updates on row modifications.

CONSTRAINS:
-----------
	Constrains are some set of rules or restriction which are applied or enforced over the columns

1. NOT NULL: it is ensuring the column should not contain any null values means every cell must contain a value
2. UNIQUE: (Distinct) it used to identify the column uniquely.
3. PRIMARY KEY: it is a combination of NOT NULL and UNIQUE and it is used to identify and rows uniquely
4. FOREIGN KEY: it is used to establish a relation b/w two or more tables, yo become a foreign key in a one table it should be primary key in parent table

5. CHECK(Condition): use to apply Conditions on columns. every value should satisfy this condition before entering the table

6. DEFAULT: it is a constrain which defined value is automatically updated/ if we are not specifying during insertion time

ENTITY: Anything which is exist in real world is called entity.

	TYPES OF ENTITY
	1. Physical/ Tangible Entity : ex: Laptop, marker...
		Entity which are having physical Structure
	2. Conceptual/ Intangible Entity: ex: Internet, Air
		Entity which are not have any physical Structure

ATTRIBUTES: are properties or characteristics of entity

	TYPES OF ATTRIBUTES:

	1. Simple attributes: attribute which can't be divided into Further attributes
		ex: Age, Phone_No
	2. Composite Attributes:
		ex: Name, DOB, Address
	3. Single valued Attribute: Attribute which are having Single value
		ex: Name, Age, Aadhar_no
	4. Multi valued Attribute: Attribute which are having More then one value
		ex: Phone_no, Emails
	5. Derived Attributes: one attribute derived from another attributes
		ex: Age is derived from DOB
	6. Key Attributes: attribute which can be identified uniquely
		ex: ID's

RELATIONSHIP: It is a association among two or more entities/tables. these relationships are established using primary key and foreign key

	Types of relationship/ Cardinality ratio

	+ 1 : 1	One entity is having direct relationship b/w another entity
		ex: user table and user profile table
	+ 1 : M	One entity is having  relationship b/w multiple/many entity
		ex: department and students

	+ M : N	many entity is having relationship b/w multiple/many entity

DDL: It is used to create or alter the table, and it will work only on the table Structure not with the data inside the table

+ TO ADD A COLUMN INTO THE EXISTING TABLE

+ TO ADD A COLUMN INTO THE EXISTING TABLE AFTER COLUMN_NAME

	  EX: ALTER TABLE EMPLOYEE RENAME COLUMN EMAIL TO EMP_EMAIL;

+ CHANGE THE DATATYPE OF EXISTING COLUMN FROM THE TABLE

FUNCTIONS: ARE BUILT IN PROGRAMS WHICH ARE USED TO PERFORM SPECIFIC TASKS.
----------
	SELECT FUNCTION(COLUMN_NAME)  FROM TABLE_NAME;

2 TYPES OF FUNCTION 
	+ SINGLE ROW FUNCTION
	+ MULTI ROW FUNCTION

+ SINGLE ROW FUNCTION: IT WILL PERFORM THE FUNCTIONS ON EACH ROW AT A TIME AND RETURN THE RESULT FOR EACH ROW

5 TYPES OF SINGLE ROW FUNCTION
++ STRING FUNCTIONS:
	+++ UPPER(): IT WILL CONVERT THE LOWER CASE CHARACTER INTO UPPER CASE
		SELECT UPPER(FNAME) FROM EMP_LOG;
		SELECT *, UPPER(FNAME) FROM EMP_LOG;
		SELECT UPPER('tarunrb');

	+++ LOWER(): IT WILL CONVERT THE UPPER CASE CHARACTER INTO LOWER CASE
		SELECT LOWER(FNAME) FROM EMP_LOG;
		SELECT *, LOWER(FNAME) FROM EMP_LOG;
		SELECT LOWER('TARUNRB');

	+++ LENGTH(): IT RETURNS THE LENGTH OF STRING
		SELECT LENGTH(FNAME) FROM EMP_LOG;
		SELECT *, LENGTH(FNAME) FROM EMP_LOG WHERE E_ID=1;
		SELECT LENGTH('TARUNRB');

	+++ CONCAT(): IT RETURNS THE LENGTH OF STRING
		SELECT CONCAT(FNAME, LNAME) FROM EMP_LOG;
		SELECT *, LENGTH(FNAME, LNAME) FROM EMP_LOG WHERE E_ID=1;
		SELECT LENGTH('TARUNRB');
		SELECT CONCAT(FNAME,' ', LNAME, 'AGE IS ', E_AGE) FROM EMP_LOG LIMIT 3;

HAVING CLAUSE: 
+ FILTERS GROUPED DATA AFTER AN AGGREGATION HAS OCCURRED. IT WORKS EXACTLY LIKE A WHERE CLAUSE, BUT INSTEAD OF FILTERING INDIVIDUAL ROWS, IT FILTERS ENTIRE GROUPS CREATED BY THE GROUP BY CLAUSE.

+ YOU CANNOT USE AGGREGATE FUNCTIONS (LIKE SUM(), COUNT(), AVG(), MAX(), OR MIN()) INSIDE A STANDARD WHERE CLAUSE. IF YOU TRY, THE DATABASE WILL THROW AN ERROR. THE HAVING CLAUSE WAS ADDED TO SQL SPECIFICALLY TO ALLOW FILTERING BASED ON THESE AGGREGATED CALCULATIONS.


+ SYNTAX: THE HAVING CLAUSE MUST ALWAYS BE PLACED AFTER THE GROUP BY CLAUSE AND BEFORE THE ORDER BY CLAUSE. 

	SELECT COLUMN_NAME, AGGREGATE_FUNCTION(COLUMN_NAME) FROM TABLE_NAME
	GROUP BY COLUMN_NAME
	HAVING AGGREGATE_FUNCTION(COLUMN_NAME) condition;

SUB QUERE: A SUBQUERY IS A QUERY WHICH IS NESTED INSIDE ANOTHER QUERY.
+ THE SUBQUERY MUST RETURN ONLY ONE COLUMN, UNLESS IT IS BEING USED WITH THE EXISTS OPERATOR. 

+ HE DATA YOUR SUBQUERY RETURNS MUST MATCH WHAT THE OUTER QUERY OPERATOR EXPECTS. 

+ SINGLE VALUE CONDITION (SCALAR): IF YOU USE BASIC COMPARISON OPERATORS (=, >, <, !=), YOUR SUBQUERY MUST RETURN EXACTLY ONE COLUMN AND ONE ROW. 

+ LIST CONDITION (MULTIPLE ROWS): IF YOUR SUBQUERY RETURNS MULTIPLE ROWS OF DATA, YOU MUST USE LIST OPERATORS LIKE IN, NOT IN, ANY, OR ALL.

	SELECT * FROM EMP_LOG WHERE DEPT_ID IN (SELECT DEPT_ID FROM EMP_LOG GROUP BY DEPT_ID HAVING AVG(SALARY)>50000);

JOINS: JOINS ARE USED TO COMBINE 2 OR MORE TABLES BY USING COMMON OR RELATED COLUMNS FROM BOTH THE TABLES.

	SYNTAX: SELECT COLUMNS FROM TAB1 (T1) TYPE OF JOIN TAB2 (T2) ON T1.COMMON_COL= T2.COMMON_COL

	TYPES OF JOINS:
	1. INNER JOIN: JOIN WHICH RETURNS ONLY MATCHING RECORDS FROM THE BOTH TABLE

	2. LEFT JOIN: IT RETURNS ALL THE RECORDS FROM LEFT TABLE AND ONLY MATCHING RECORDS FROM RIGHT TABLE
	
	3. RIGHT JOIN: IT RETURNS ALL THE RECORDS FROM RIGHT TABLE AND ONLY MATCHING RECORDS FROM LEFT TABLE

	4. CROSS JOIN: IT RETURNS ALL POSSIBLE COMBINATIONS FROM TABLES

	5. SELF JOIN: ANY ONE OF THE ROW FROM THE TABLE IS JOINNG WITH THE SAME TABLE

    		SELECT E.FNAME,D.D_NAME FROM EMP_LOG E RIGHT JOIN DEPT D ON E.DEPT_ID=D.D_ID WHERE E.FNAME IS NULL;
